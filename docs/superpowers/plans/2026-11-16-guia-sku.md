# Guía de SKU y proveedores en la Ficha (paso 5) — plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Que Eunice toque cualquier SKU en Cotiza y vea qué significa cada parte (categoría, modelo y color con su circulito), con las tablas completas de letras leídas de Odoo, y que en la Ficha (i) vea los proveedores con su código para copiarlo.

**Architecture:** `/api/catalogo` agrega (solo lectura) las tablas de letras de Odoo (`tablas.categorias` y `tablas.colores`) y, por producto, su letra de categoría (`catL`) y su color (`col`). Un módulo puro nuevo `public/js/sku.js` desarma un SKU (formato nuevo `K`+letra+3 dígitos+letra, o el actual `KU-CAT-MODELO-COL`) con esas tablas y los datos del producto. La guía es una capa propia encima de todo (no es una ruta ni la hoja inferior), así que abrirla desde el selector no pierde la búsqueda.

**Tech Stack:** JS sin framework, Cloudflare Pages Functions, Driver.js, Node para pruebas, Playwright para la prueba de pantalla.

**Spec:** `docs/superpowers/specs/2026-11-16-sku-cortos-design.md` (tabla "Kuukum Cotiza": filas "SKU en pantalla", "Guía de SKU" y "Proveedores en la Ficha"; orden de trabajo, paso 5).

## Global Constraints
- Odoo solo se lee. Las letras y los colores salen de Odoo (`product.category.x_sku_letra`, `product.attribute.value.x_sku_letra` y `html_color` del atributo COLOR id 10); nada de tablas escritas en el código.
- Los códigos de proveedor solo se ven en la Ficha y en la guía; no van al PDF, al WhatsApp del cliente ni a la cotización guardada.
- Funciona con los SKU de hoy (`KU-PLU-1115A-NEG`) y con los nuevos (`KP004N`), porque la ventana de renombrado es después.
- La guía se abre desde: el SKU en los resultados del selector, el SKU en la Ficha (i) y Ajustes → "Guía de SKU" (sin SKU: solo tablas).
- Tocar el SKU en un resultado abre la guía y **no** elige el producto.
- Nueva función = su recorrido guiado. Versión `0.4.21` con `scripts/bump-version.mjs`.
- Nada se publica sin autorización de Victor.

## Review Focus
- Producto sin color (sets de BeePrint, servicios) → la guía muestra categoría y modelo, y en color "Sin color".
- SKU que no sigue ningún formato (productos propios sin SKU, `KK-LIBRE`) → no se muestra como tocable; si se llega a abrir, dice "Este código no sigue el formato de Kuu Kum" y muestra las tablas.
- Letra de color que no está en la tabla de Odoo (alguien la borró) → la cajita se muestra con "Color no registrado", sin romper la guía.
- Catálogo guardado en el teléfono de una versión anterior (sin `tablas`) → la guía no truena; pide "Actualizar catálogo" en Ajustes.
- Abrir la guía desde el selector y cerrarla → el selector sigue abierto con el mismo texto y resultados.

### Task 2: `sku.js` — desarmar un SKU

**Files:**
- Create: `public/js/sku.js`
- Create: `scripts/test-sku.mjs`; `package.json` script `"test:sku"`

**Interfaces:**
- Consumes: `tablas` y producto (`code`, `cat`, `catL`, `col`) de Task 1.
- Produces: `export function desarmarSku(code: string, tablas, prod?) -> { formato: "nuevo"|"anterior"|"otro", partes: Array<{ txt: string, que: "marca"|"categoria"|"modelo"|"color", nombre: string, hex?: string }> }`.

- [ ] **Step 1: Prueba que falla** (`scripts/test-sku.mjs`, estilo `ok()` de las otras pruebas) con `tablas = { categorias: [{l:"P",n:"Plumas"},{l:"K",n:"Sets corporativos"}], colores: [{l:"N",n:"Negro",hex:"#1A1A1A"}] }`:
```js
const a = desarmarSku("KP004N", tablas);
ok(a.formato === "nuevo" && a.partes.map((p) => p.txt).join("|") === "K|P|004|N", "nuevo: K · P · 004 · N");
ok(a.partes[1].nombre === "Plumas" && a.partes[2].nombre === "Modelo 4" && a.partes[3].nombre === "Negro" && a.partes[3].hex === "#1A1A1A", "nuevo: nombres y circulito");
ok(desarmarSku("kp004n", tablas).formato === "nuevo", "nuevo: minúsculas");
ok(desarmarSku("KK001", tablas).partes.length === 3, "nuevo sin color: 5 caracteres");
const b = desarmarSku("KU-PLU-1115A-NEG", tablas, { cat: "Plumas", col: { n: "Negro", hex: "#1A1A1A" } });
ok(b.formato === "anterior" && b.partes.map((p) => p.txt).join("|") === "KU|PLU|1115A|NEG" && b.partes[2].nombre === "Modelo del proveedor" && b.partes[3].nombre === "Negro", "anterior: con categoría y color del producto");
ok(desarmarSku("KP004Z", tablas).partes[3].nombre === "Color no registrado", "letra de color que no está en Odoo");
ok(desarmarSku("KK-LIBRE", tablas).formato === "otro" && desarmarSku("", tablas).formato === "otro", "otros códigos");
```
- [ ] **Step 2: Correr y ver que falla.** `npm run test:sku` → módulo no existe.
- [ ] **Step 3: Implementar** `desarmarSku`. Nuevo: `/^K([A-HJ-NP-Z])(\d{3})([A-Z0-9])?$/i` (sin I ni O en la categoría). Anterior: `/^KU-([A-Z]{3})-([A-Z0-9]+)(?:-([A-Z0-9]+))?$/i`, con nombres tomados de `prod`. Sin `tablas`, los nombres quedan vacíos.
- [ ] **Step 4: Correr y ver que pasa.** `npm run test:sku` → todas `✓`.
